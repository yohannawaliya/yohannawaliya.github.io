Getting Raw Text Into SAO Rows

⏱ 15 min

If you're starting from real newspaper text rather than the pre-coded corpus, this is how a sentence becomes one row of structured data. Skip to Stage 1 if you're using the provided CSV.

💡 The one-sentence version

Every clause you code answers three questions: Who acted (Subject) · What did they do (Action, reduced to a category like repression or demand) · On whom or what (Object). Everything else in the schema (place, year, intensity) is optional enrichment.

manual_coding_example.R 
# Take a real sentence:
# "Police arrested twelve union organizers outside the factory gate."
#
# Break it into the SAO schema by hand:

one_clause <- tribble(
  ~doc_id,      ~subject, ~sub_type, ~verb,      ~verb_type,   ~object,      ~obj_type, ~year, ~place,       ~quantity, ~intensity,
  "NYT_1919_03", "police", "state",   "arrested", "repression", "organizers", "person", 1919,  "Pittsburgh", 12,       "high"
)
How each column was decided

subject = "police" (literal noun) → sub_type = "state" (theoretical category, defined in your codebook). verb = "arrested" (literal) → verb_type = "repression" (your controlled vocabulary term). quantity = 12 comes straight from the text. intensity = "high" is a judgment call — arrests of organizers rate higher than, say, a routine negotiation.

"Police…"subject / sub_typepolice / state
"…arrested…"verb / verb_typearrested / repression
"…twelve union organizers…"object / obj_type / quantityorganizers / person / 12

⚠ Common parsing traps

Passive voice inverts subject/object: "Organizers were arrested by police" — the grammatical subject ("organizers") is semantically the target. Code by who did the acting, not sentence position. Multi-word verbs: "went on strike" is one verb_type (collective_action), not three tokens. Nominalisations: "the strike continued" hides the action inside a noun — you may need to infer the underlying verb.

✅ Scaling up beyond hand-coding

For corpora larger than ~50 articles, use udpipe (R) or spaCy (Python) to auto-tag part-of-speech and dependency relations (nsubj → Subject, ROOT verb → Action, obj → Object), then hand-correct the theoretical typing (sub_type, verb_type) — that classification step always needs a human. Franzosi's own PC-ACE software (free, pc-ace.com) is built exactly for this workflow at scale.

Frequency Analysis — Who Acts, and How?

⏱ 10 min

The simplest QNA output. Actor frequency is a proxy for narrative presence — who gets to be the subject of the story.

02_frequency.R 
actor_freq <- sao |>
  count(subject, sub_type, sort = TRUE) |>
  rename(frequency = n)
print(actor_freq)

class_freq <- sao |>
  count(sub_type, sort = TRUE) |>
  mutate(pct = round(n / sum(n) * 100, 1))
print(class_freq)

action_dist <- sao |>
  count(verb_type, sort = TRUE) |>
  mutate(pct = round(n / sum(n) * 100, 1))

p_freq <- ggplot(action_dist, aes(x = reorder(verb_type, pct), y = pct)) +
  geom_col(fill = "#e85d42", alpha = 0.85) +
  geom_text(aes(label = sprintf("%.1f%%", pct)), hjust = -0.15, size = 3.2) +
  coord_flip() +
  labs(title = "Franzosi SAO — Action Type Distribution", x = "", y = "% of coded clauses") +
  theme_minimal(base_size = 12)
print(p_freq)
ggsave("output_01_action_distribution.png", p_freq, width = 8, height = 5, dpi = 150)

S × A Cross-Tabulation — "Who Does What"

⏱ 10 min

Franzosi's central table. Rows = actor class, columns = action type. Empty cells are as meaningful as filled ones.

03_crosstab.R 
who_does_what <- sao |>
  count(sub_type, verb_type) |>
  pivot_wider(names_from = verb_type, values_from = n, values_fill = 0)
print(who_does_what)

sxa_long <- sao |> count(sub_type, verb_type)
p_heat <- ggplot(sxa_long, aes(x = verb_type, y = sub_type, fill = n)) +
  geom_tile(colour = "white", linewidth = 0.5) +
  geom_text(aes(label = n), size = 3.5, fontface = "bold") +
  scale_fill_gradient(low = "#f4ede0", high = "#e85d42") +
  labs(title = "S \u00d7 A Matrix — Who Does What to Whom", x = "Action Type", y = "Actor Class", fill = "Clauses") +
  theme_minimal(base_size = 12) +
  theme(axis.text.x = element_text(angle = 35, hjust = 1))
print(p_heat)
ggsave("output_02_sxa_heatmap.png", p_heat, width = 10, height = 4, dpi = 150)
Reading it

Labor's repertoire spans 9 distinct actions — the broadest of the three classes. State is narrow: repression and intervention only, a purely coercive toolkit. Capital moves through refusal → dismissal → concession, a three-stage arc. The empty cells matter: the state never celebrates, capital never petitions. Those absences are structural constraints on the narrative world, not gaps in your data.

Actor Network — Directed Power Relations

⏱ 10 min

When the object of a clause is itself an actor, that clause becomes a directed edge. Centrality metrics reveal power structure frequency counts alone can't show.

04_network.R 
actor_edges <- sao |>
  filter(obj_type %in% c("actor", "person")) |>
  select(from = subject, to = object, action = verb, verb_type, year)

g <- graph_from_data_frame(actor_edges, directed = TRUE)

p_net <- ggraph(g, layout = "stress") +
  geom_edge_arc(aes(label = action, colour = verb_type),
    arrow = arrow(length = unit(3, "mm"), type = "closed"),
    end_cap = circle(5, "mm"), start_cap = circle(5, "mm"), label_size = 2.8) +
  geom_node_point(size = 9, colour = "#1a2744") +
  geom_node_text(aes(label = name), repel = TRUE, size = 3.4) +
  theme_graph()
print(p_net)
ggsave("output_03_actor_network.png", p_net, width = 9, height = 7, dpi = 150)

cat("In-degree:\n");  print(sort(degree(g, mode="in"),  decreasing=TRUE))
cat("Out-degree:\n"); print(sort(degree(g, mode="out"), decreasing=TRUE))
cat("Betweenness:\n"); print(round(sort(betweenness(g), decreasing=TRUE), 3))
▶ Console output
In-degree: management 200 workers crowd organizers police forces 1 1 1 1 1 Out-degree: police union strikers 2 1 1 Betweenness: management (all others: 0.000) 0.024
Reading it

Police out-degree = 2: the state's most active directed agent — it arrests organizers and disperses crowds. Management betweenness = 0.024 is the only non-zero broker score: management sits at the hinge between labor negotiation and capital dismissal. Everyone with in-degree = 1 is a one-time narrative target. The overall picture: workers and their allies are structurally acted-upon; police and management are structurally acting.

Protest Intensity Index — Escalation Over Time

⏱ 10 min

A composite score (action weight × intensity) summed by year and actor class. This is where the corpus becomes a readable time-series.

05_pii.R 
pii <- sao |>
  mutate(
    intensity_score = case_when(
      intensity == "high"   ~ 3,
      intensity == "medium" ~ 2,
      intensity == "low"    ~ 1),
    action_weight = case_when(
      verb_type %in% c("collective_action","confrontation","occupation") ~ 3,
      verb_type %in% c("repression","dismissal","refusal")              ~ 2,
      verb_type %in% c("demand","petition","intervention")             ~ 2,
      TRUE                                                                ~ 1),
    pii_score = intensity_score * action_weight)

pii_summary <- pii |>
  group_by(year, sub_type) |>
  summarise(total_pii = sum(pii_score), .groups = "drop")
print(pii_summary)

p_pii <- ggplot(pii_summary, aes(x = year, y = total_pii, colour = sub_type, group = sub_type)) +
  geom_line(linewidth = 1.3) + geom_point(size = 3.5) +
  scale_colour_manual(values = c(labor="#e85d42", state="#1a2744", capital="#c8a96e")) +
  labs(title = "Protest Intensity Index by Actor Class", x = "Year", y = "Total PII", colour = "Actor Class") +
  theme_minimal(base_size = 12)
print(p_pii)
ggsave("output_04_pii_trajectory.png", p_pii, width = 9, height = 5, dpi = 150)

The full arc — escalate, confront, settle — is now a readable time-series instead of buried in prose.

Fixing the Errors You'll Actually Hit

Every one of these has come up in a workshop. Find your error message, apply the fix, keep going.

You see thisWhat it meansFix
Error: 'labour_corpus...csv' does not exist R is looking in the wrong folder Run getwd() to see where R is looking. Either move the CSV there, or run setwd("path/to/folder") first.
could not find function "graph_from_data_frame" igraph isn't loaded (or installed) Run library(igraph). If that errors too, run install.packages("igraph") first.
Error in geom_edge_arc(): could not find function ggraph isn't loaded install.packages("ggraph") then library(ggraph). This is separate from ggplot2.
Plot window shows nothing / blank You assigned the plot but didn't print it In a script (not console), ggplot(...) needs an explicit print(p) to render. The provided script already does this.
object 'sub_type' not found Column name typo, or you're using your own CSV with different headers Run names(sao) to see your actual column names. They must exactly match: doc_id, subject, sub_type, verb, verb_type, object, obj_type, year, place, quantity, intensity.
Network graph looks empty or has 1 node No rows have obj_type of "actor" or "person" Check your obj_type column — only rows where the object is itself a social actor become network edges. This is by design, not a bug.
non-numeric argument to binary operator in the PII step Your intensity or verb_type values don't exactly match the strings in case_when() Check for typos, extra spaces, or capitalization mismatches: "High" ≠ "high". Run unique(sao$intensity) to see exactly what's in your data.
Heatmap / bar chart colors look wrong You renamed a category but didn't update the color-mapping code Search the script for scale_colour_manual / scale_fill_manual and make sure every category name in your data has a matching entry.
Warning: Removed N rows containing missing values NA values in a column being plotted (usually quantity) This is expected and harmless if it's the quantity column — not every clause reports a number. Confirm with the completeness audit below.
🔧 The audit block — run this before trusting any result

Paste this after loading your own data. It won't fix your data, but it will tell you exactly where the problems are before they quietly wreck your frequency counts.

audit.R 
# Field completeness — what % of clauses have each field filled in?
completeness <- sao |>
  summarise(across(everything(), ~round(mean(!is.na(.)) * 100, 1))) |>
  pivot_longer(everything(), names_to = "field", values_to = "pct_complete") |>
  arrange(pct_complete)
print(completeness)

# Controlled vocabulary check — did a typo sneak a new category in?
valid_sub_types <- c("labor", "state", "capital")
sao |> filter(!sub_type %in% valid_sub_types) |> count(sub_type)

# Duplicate clauses — did the same event get coded twice?
sao |> group_by(doc_id, subject, verb, object) |> filter(n() > 1)

Coding Your Own Texts

The blank worksheet and codebook template downloaded above are built for this. Here's the order of operations that actually works in a room full of people coding together.

  • ✓ Before opening the worksheet: fill out the codebook template's category tables first. Decide your sub_type and verb_type categories as a group, in writing, before anyone codes a single clause.
  • ✓ Pilot on 10 clauses: two people code the same 10 clauses independently. Compare. Where you disagree, that's a codebook gap — fix the definition, not just the disputed row.
  • ✓ Code in the worksheet CSV, one row per clause, using the exact column headers already in the file.
  • ✓ Run the audit block (above) on your worksheet before doing any analysis — catch typos and gaps early.
  • ✓ Swap the file path in Stage 1's read_csv() call to point at your worksheet instead of the demo corpus. Everything downstream runs unchanged.
